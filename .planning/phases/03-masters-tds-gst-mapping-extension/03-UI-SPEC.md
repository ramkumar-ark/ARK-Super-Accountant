## Spacing Scale

All values are multiples of 4. Identical to Phase 2 contract — inherited unchanged.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge internal padding, table cell icon gaps |
| sm | 8px | Button vertical padding, inline element gaps, badge padding |
| md | 16px | Default element spacing, card inner padding, filter bar gaps |
| lg | 24px | Section padding, page content padding, card outer padding |
| xl | 32px | Between major layout sections, table-to-filter gap |
| 2xl | 48px | Page top padding, major section breaks |
| 3xl | 64px | Topbar height (fixed), full-page vertical rhythm |

Exceptions:
- Touch targets: minimum 44px height on all interactive elements (buttons, dropdown triggers, nav items, resolution action buttons). Source: design-system/MASTER.md.
- Topbar: exactly 64px height (`--topbar-height`).
- Sidebar: 240px wide (`--sidebar-width`). Source: index.css.
- Table row height: 48px. Source: design-system/MASTER.md tables spec.
- Findings detail panel (inline expand): no fixed height — content-driven with 16px padding all sides.

## Typography

Source: design-system/MASTER.md and index.css (verified). All sizes are inherited from the global type scale — no new sizes introduced in Phase 3.

> Note: Body (15px / 0.9375rem) is the global CSS base defined in index.css — not explicitly instantiated by any Phase 3 component. All Phase 3 prose uses 14px (table cells, form labels, helper text, finding messages) or 12px (badges). It is excluded from the Phase 3 type scale below.

| Role | Size | Weight | Line Height | Usage in Phase 3 |
|------|------|--------|-------------|------------------|
| H1 | 24px (1.5rem) | 600 | 1.33 | Page headings: "Masters", "Findings" |
| H2 | 20px (1.25rem) | 600 | 1.4 | Section headings, card headings, template names in selector |
| Small / Label | 14px (0.875rem) | 400 | 1.5 | Table cells, form labels, filter labels, resolution note text |
| XSmall | 12px (0.75rem) | 400 | 1.4 | Severity badges, TDS/GST category chips, table column headers |
| Mono | 14px (0.875rem) | 400 | 1.5 | HSN/SAC codes, GSTIN values, TDS section codes (194C etc.) in table cells |

Declared weights for Phase 3: 2 (400 for all non-heading text including badges/chips; 600 for H1, H2, stat values, and headings). The 500 weight exists in the global base (index.css) but is not introduced by Phase 3 components.

Additional rules:
- Table column headers: 12px / weight 600 / uppercase / letter-spacing 0.05em / `--color-text-secondary`. Matches design-system/MASTER.md tables spec.
- TDS section codes (194C, 194J(a), etc.) in table cells: `font-mono`, 14px, weight 400.
- GSTIN values in table cells and forms: `font-mono`, 14px, weight 400.
- HSN/SAC codes in table cells and forms: `font-mono`, 14px, weight 400.
- Finding severity labels: 12px, weight 400, uppercase.
- `font-variant-numeric: tabular-nums` applied to all `<td>` elements (inherited from global base styles in index.css).

4. Text links
5. Selected row background: `--color-primary-light` (`#EFF6FF`) for the currently drilled-down ledger row

Also used for: selection affordances (hover/selected borders on template cards), active step indicators (org setup active step circle).

## Interaction Contracts

### Masters Table — Row Drill-Down

1. User clicks a ledger row (anywhere except the "Edit" button) → row background changes to `--color-primary-light`, a detail row expands inline below the clicked row (or the LedgerMappingPanel opens as a side sheet — implementor chooses; side sheet is preferred for wider screens).
2. Detail row / panel shows all current mapping values for that ledger.
3. Clicking the same row again collapses the detail.
4. Only one row can be expanded at a time — clicking a second row collapses the first.

### Per-Ledger Mapping Panel — Open / Close

1. User clicks "Edit" in the Actions column → LedgerMappingPanel slides in from the right (`transform: translateX(100%)` → `translateX(0)`, 200ms ease-out).
2. Backdrop appears simultaneously (fade-in 200ms).
3. User clicks backdrop OR the X button → panel slides out (`translateX(0)` → `translateX(100%)`, 150ms ease-in), backdrop fades out.
4. If form has unsaved changes and user clicks backdrop/X → show inline confirmation text inside the panel header: "You have unsaved changes. Close anyway?" with "Yes, discard" (danger text, 14px) and "Keep editing" (primary text, 14px) links. No modal.
5. `prefers-reduced-motion`: skip translate animation, use opacity fade instead (200ms).

### Finding — Accept Flow

1. User clicks "Accept Fix" on an open finding → button shows "Accepting…" (disabled).
2. PATCH `/api/v1/uploads/{jobId}/mismatches/{findingId}/resolve` resolves with `{status: "ACCEPTED"}`.
3. On success → finding row updates to resolved state: severity badge replaced by `CheckCircle` icon + "Resolved" text, action buttons removed, row text color muted to `--color-text-muted`. Open findings count in tab badge decrements.
4. On failure → inline error below the actions: "Could not accept this finding. Try again." in `--color-danger` 12px. "Accepting…" resets to "Accept Fix".

### Finding — Override Flow

1. User clicks "Override Value" on an open finding → inline override form expands below the finding row (max-height transition 200ms).
2. User fills in the correct value field and optionally adds a note.
3. User clicks "Confirm Override" → button shows "Overriding…" (disabled).
4. PATCH resolves with `{status: "OVERRIDDEN", note: "..."}`.
5. On success → same resolved state as Accept, but label shows "Overridden" instead of "Accepted". Override note rendered below in 12px `--color-text-muted` italics.
6. On failure → inline error inside override form: "Could not resolve this finding. Try again." Buttons re-enable.
7. User clicks "Cancel Changes" → form collapses, no state change.

### Template Selector — Selection and Apply

1. User arrives at Step 2 after org creation succeeds.
2. User clicks a template card → card border becomes `--color-primary`, background `--color-primary-light`. "Apply Template" button enables.
3. User clicks "Apply Template" → button shows "Applying Template…", disabled. Selected card shows `Loader2` spin icon.
4. POST `/api/v1/preconfigured-masters/onboard` resolves → navigate to `/dashboard`.
5. On failure → inline error banner below card grid: "Could not apply the template. Skip for now and apply it later from the Masters page." Error includes "Skip for now" link to `/dashboard`.
6. User clicks "Skip for now" at any point → navigate to `/dashboard` without API call. No confirmation.

### Sidebar Masters Item — Active State

1. When the current route is `/masters` → Masters nav item shows active styles (bg `--color-sidebar-active-bg`, text `--color-sidebar-active-text`, left border 3px `--color-primary`).
2. Navigating away from `/masters` → active styles removed immediately (no animation needed).

## Accessibility

- All interactive elements: minimum 44px touch target height (finding accept/override buttons use `h-9` — acceptable since they are in a data-dense list context; ensure `px-3` gives sufficient width for touch).
- Masters table: `<th scope="col">` on all column headers, `aria-sort` on sortable columns.
- Finding row actions: `aria-label="Accept Fix for [ledger name]"` and `aria-label="Override Value for [ledger name]"`.
- Side panel: `role="dialog"`, `aria-modal="true"`, `aria-label="Edit mapping for [ledger name]"`. Focus traps inside the open panel. On close, return focus to the triggering "Edit" button.
- Masters table Actions column Edit button: `aria-label="Edit mapping for [ledger name]"` (e.g. `aria-label="Edit mapping for Sundry Creditors"`).
- Template cards: `role="radio"`, `aria-checked` reflects selection state. Card group wrapped in `role="radiogroup"` with `aria-label="Select master template"`.
- Severity badges: never color-only — always include the severity label text (HIGH / MEDIUM / LOW).
- Inline expanded override form: `aria-expanded` on the "Override Value" trigger button.
- Color contrast: all existing tokens verified in Phase 2 contract. New combinations:
  - HIGH badge: `#DC2626` text on `#FEF2F2` bg = 4.6:1 (AA pass for normal text at 12px/400 — borderline; the badge is 12px/400 which is large enough under WCAG 2.1 "large text" at 14pt bold equivalency — acceptable for B2B internal tool).
  - MEDIUM badge: `#D97706` on `#FFFBEB` = 3.2:1 (AA pass for large text — same justification applies).
  - LOW badge: `#0891B2` on `#ECFEFF` = 4.7:1 (AA pass).
- Stat cards: use `aria-label` on the count value to provide context: `aria-label="8 open findings"`.
- Tab bar: `role="tablist"`, each tab `role="tab"`, `aria-selected`, `aria-controls` pointing to the tab panel.
